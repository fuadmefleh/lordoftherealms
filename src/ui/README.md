## Rendering Pipeline

```
ui/game.js  (rAF loop)
   ├── ui/renderer.js          → draws world hex map on canvas
   ├── ui/innerMap/index.js    → draws inner-map canvas (when active)
   ├── ui/ui.js                → draws HUD overlay
   └── ui/lightSystem.js       → draws light layer on top
```

## Where panels are reached

One home per kind of panel, so nothing is reachable three inconsistent ways:

- **Action menu** (click your hex or a town; `actionMenu/core.js`): everything done *in a place*, by district seal (At Hand, Hearth/Camp, Market, Tavern & Temple, Hall & Court, Arms, Works, Frontier, Maps) and, in big districts, folders (`AMX_GROUPS`; every type in a folder must map to that district in `_categorizeActions`, or it lands in "More").
- **Top bar** (`components/TopBar.jsx`, wired in `ui/hud.js`): overviews. **Map** (overlays + the eight map modes, M cycles) · **Character** (sheet, inventory, party, relationships, House; treasury, properties) · **Realm** (realms & diplomacy, settlements, council, laws; technology, religion, peoples; economic chronicle, trends, kingdom comparison) · **Quests** · **Journal** (your story / the world / the days, each a captioned group) · **Counsel** (what needs you now, each matter a row that opens its panel). The portrait opens the Character Sheet, the gold chip the finances, the Prestige chip the House, the date the Calendar, ? the How to Play panel.
- **Bottom turn bar**: speed, standing order, Wait…, a week, End Turn. (The top bar's old ⏳ duplicate and the left icon rail, which only repeated top-bar items, are gone.)
- **Keys**: Enter end day, Shift+Enter a week, Space pause, 1–3 speed, I inventory, M map mode, G trade-map good, C centre, Esc close / stop / leave.

## Integration Points

- **Depends on**: `world/`, `player/`, `systems/audio/`, `core/hex.js`
- **Used by**: `context/GameContext.jsx` (mounts the canvases and starts the loop)

## Notes

- All rendering is canvas-based (`<canvas>`), not DOM/CSS. React only handles the screen shells (title screen, settings, overlays).
- `ui/game.js` is the single source of truth for the game tick — it calls `world.processDay()` and all system `processDay()` functions in the correct order.
- `ui/innerMap/` merges the previously separate `innerMapLayers.js`, `innerMapRenderer.js`, and `innerMapCombat.js` into a cohesive subfolder. See `ui/innerMap/README.md`.
- Do not put game logic here — only reads state and dispatches to `PlayerActions` / system methods.
